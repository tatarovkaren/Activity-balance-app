# Справочник продуктов

Кнопка «＋ Продукт» на экране «День» → экран `src/screens/Food.tsx`: поиск по названию, свои продукты,
штрихкод. Выбранные продукты записываются одним приёмом пищи (`provider: 'catalog'`) — той же записью,
что и приём по фото (`DayEntry.photoMeals`), поэтому сложение с ручным вводом и импортом FatSecret
одинаковое (см. `src/core/photo/meals.ts`). На «Дне» у записи пометка «из справочника» и точные цифры
без диапазона.

## Где что

| Файл | Что |
|---|---|
| `src/core/photo/foods.ts` | тип `Food`, 36 продуктов фото-подсчёта (`BASE`), сборка ядра, `FOODS`, `FOOD_BY_ID` |
| `src/core/photo/catalog.ts` | ядро: ~310 строк `[id, ru, en, ккал, Б, Ж, У, источник, {порция, штука, другие названия}]` |
| `src/core/photo/search.ts` | поиск RU/EN по началу слова, падежи, жирность цифрами («кефир 2,5»), штрихкод |
| `src/core/photo/custom.ts` | свои продукты, проверка ввода, приём из справочника (`mealFromFoods`) |
| `src/core/photo/off.ts` | Open Food Facts: штрихкод, поиск магазинных товаров по названию (только по кнопке: лимит ~10 поисков в минуту), ответ → свой продукт |
| `src/ui/barcode.ts` | штрихкод со снимка через `BarcodeDetector` браузера |

## Источники

- `usda` — USDA FoodData Central, SR Legacy (общественное достояние). Округлено.
- `ru` — средние значения российских таблиц химического состава.
- `label` — типичная маркировка (молочка по жирности, хлеб, снеки).
- `recipe` — расчёт по типовой домашней рецептуре, ориентир ±15 %.
- `user` — свой продукт пользователя (или куратора, поле `author`).
- `off` — Open Food Facts по штрихкоду. Лицензия ODbL: в приложении подпись источника.

Значения внесены вручную. Тест `src/core/photo/catalog.test.ts` проверяет, что ккал сходятся с
Б×4 + Ж×9 + У×4 (до 16 %, у низкокалорийных овощей до 25 %, алкоголь исключён), id уникальные,
у всех есть английское название и источник.

## Добавить продукт в ядро

1. Строка в нужной категории `catalog.ts`; id латиницей, не менять после выпуска (на него ссылаются записи).
2. `npm test` — проверка энергии поймает опечатку.
3. id фото-подсчёта (`PHOTO_FOOD_IDS`) и список на сервере (`supabase/functions/photo-estimate/logic.ts`)
   трогать не нужно: модель видит короткий список и для остального присылает свои цифры на 100 г.

## Свои продукты

`AppData.customFoods` — на устройстве и в резервной копии (слияние по id, побеждает более новая правка).
Поля `author`, `createdAt`, `updatedAt` — задел под синхронизацию с сервером и общий список куратора.
Найденный по штрихкоду продукт сохраняется сюда же и второй раз находится без сети.

## Штрихкод

Цифры вручную работают везде. Снимок распознаётся встроенным `BarcodeDetector` (Chrome/Edge на Android и
компьютере); в Safari на iPhone его нет — там подсказка вписать цифры. В мобильном приложении — сканер
`expo-camera` (после пилота).
