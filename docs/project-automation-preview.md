# Автоматизация проекта Activity Balance

## GitHub Actions

Ветка `preview/project-automation` проверяет pull request целиком и запускает проверки при push в ветки Preview. Сборка Expo Web выполняется после проверки типов и тестов. Workflow уведомлений о релизе в Telegram исключён из проверок Preview.

## Архив Preview в Google Drive

Workflow запускается только из `preview/project-automation`. Первый push новой ветки, изменение конфигурации архивирования и изменение версии в `app.json` или `package.json` запускают архивирование. GitHub поддерживает ручной запуск после появления workflow в ветке по умолчанию. Пока workflow есть только в Preview, проверка запускается push с изменением версии или конфигурации архивирования.

В ZIP включаются отслеживаемые исходники, тесты и документы из checkout, с фильтрацией приватных путей и текста. В манифесте указаны коммит и список исключений. История архива привязана к версии и полному SHA. GitHub сохраняет ZIP и SHA-256 в артефакте; успешный шаг Drive подтверждает контрольную сумму повторным чтением.

Для испытания подготовьте отдельную папку Preview, доступную OAuth-клиенту с областью `drive.file` (например, созданную тем же клиентом). Настройте переменную `ACTIVITY_BALANCE_PREVIEW_DRIVE_FOLDER_ID` и секреты `ACTIVITY_BALANCE_DRIVE_CLIENT_ID`, `ACTIVITY_BALANCE_DRIVE_CLIENT_SECRET`, `ACTIVITY_BALANCE_DRIVE_TOKEN` в GitHub Actions. Токен — JSON OAuth rclone с refresh token. Храните его в GitHub Secrets. Повторная запись того же имени разрешена только для совпадающего содержимого.

Архив репозитория покрывает материалы, которые хранятся в Git. Для рабочих файлов вне Git, оформления решений из реестра и результатов внешнего тестирования нужен дополнительный экспорт. Пользовательские данные Supabase исключены из резервного копирования проектных материалов.

## Реестр

Опубликованный Sites-реестр — версия 1. В настройках сайта отсутствует MCP-интерфейс для изменения записей. В исходном репозитории реестра есть ветка `preview/github-issue-status`, коммит `2ebf5f1`. Карточки считывают состояние связанных GitHub Issues при открытии. Статус карточки, история и результаты проверок остаются в D1. Локально проверены открытая задача, обработка недоступности API, отсутствие дубликата #65 и сохранение ручной истории. Для живой приёмки нужен изолированный экземпляр с собственной D1.
