# Провайдер оценки по фото — как подключить модель

Приложение не привязано к конкретному ИИ. Оно отдаёт снимки и размеры руки, а получает только список продуктов и размер каждой порции. Граммы, ккал, БЖУ, диапазон ±15/20/30 %, скрытое масло и пересчёт уварки всегда считает само приложение (`src/core/photo/estimate.ts`), поэтому разные модели можно честно сравнивать на одних и тех же взвешенных эталонах.

## Варианты в приложении

| id | Что делает | Когда |
|---|---|---|
| `manual` | Без ИИ: пользователь описывает порции в кулаках, ладонях, горстях или граммах | Всегда доступно, не тратит лимит |
| `demo` | Имитирует ответ модели, не смотрит на снимок | Показ и тесты интерфейса |
| `http` | Отправляет снимки на сервер, сервер вызывает модель | Появляется, если подключён Supabase (функция `photo-estimate`) или задан свой `EXPO_PUBLIC_PHOTO_ENDPOINT` |

Без сервера по умолчанию выбран `demo`: весь путь (снимки → черновик → правка граммов → запись в дневник) работает, но снимок не анализируется — ответ одинаковый.

## Контракт сервера

`POST {EXPO_PUBLIC_PHOTO_ENDPOINT}`, заголовок `Authorization: Bearer <токен пользователя>`.

Запрос (`PhotoEstimateRequest`):

```json
{
  "photos": { "top": "data:image/jpeg;base64,...", "side": "data:image/jpeg;base64,..." },
  "hand": { "palmWidth": 10, "palmLength": 10.5, "fistWidth": 9, "fistHeight": 10, "thumbLength": 6.5, "source": "manual" },
  "note": "гречка с котлетой, ресторан",
  "locale": "ru"
}
```

Ответ (`PhotoEstimateResponse`):

```json
{
  "components": [
    { "foodId": "buckwheat", "amount": { "kind": "hand", "unit": "fist", "count": 0.7 }, "confidence": 0.7 },
    { "name": "Котлета", "per100": { "kcal": 230, "p": 17, "f": 15, "c": 7, "density": 1.0 },
      "amount": { "kind": "dims", "lengthCm": 9, "widthCm": 6, "heightCm": 2, "shape": "slab" } }
  ],
  "quality": "good",
  "oilyGuess": true,
  "retake": ["addSide"],
  "comment": "Главная погрешность — масло при жарке котлеты."
}
```

Ошибка 429 — лимит тарифа: `{ "error": "limit", "limit": 2, "per": "day" }`, приложение покажет понятный текст.

`locale` — язык интерфейса пользователя (`ru`, `en`, …). В `retake` можно прислать известный код (`addSide` — «добавьте снимок сбоку под 30–45°»), его приложение переведёт само; любой другой текст сервер присылает уже на языке `locale`. Свои названия продуктов (`name`) — тоже на языке `locale`.

`amount` бывает четырёх видов: `hand` (единицы руки), `dims` (размеры в см и форма `slab` / `mound` / `cylinder`), `volume` (мл), `grams`. Продукт — либо `foodId` из справочника `src/core/photo/foods.ts`, либо свои значения `per100`.

## Что делает сервер

Готовая реализация — `supabase/functions/photo-estimate/` (`index.ts` — запрос, `logic.ts` — промпт, схема ответа, разбор и лимиты; логику проверяют тесты `src/core/photo/server.test.ts`). Метод руки, по которому написан промпт, — `docs/hand-portion-method.md`.

1. Проверяет токен пользователя, согласие на обработку фото (`consents`, `photo_ai`) и лимит тарифа. Считается **приём пищи, а не снимок**: все блюда на столе + снимок сбоку = одна оценка. Бесплатно — 2 приёма за 24 часа, Премиум — без лимита, защита от злоупотреблений 30 за 24 часа. Тариф берётся из таблицы `subscriptions` (миграция 0004), которую пишет только биллинг: профиль пользователь правит сам. Каждая успешная оценка — строка в `photo_usage`.
2. Выбирает модель по контуру рынка пользователя: для РФ — российская модель (YandexGPT, GigaChat), чтобы фото не уходили за рубеж; вне РФ — любая (например, дешёвая модель Claude по умолчанию и сильная по кнопке «пересчитать точнее»).
3. Просит модель вернуть JSON строго по контракту выше: продукты, размеры относительно руки, качество снимков, есть ли жарка.
4. Не хранит снимки после ответа.

Ключи API живут только на сервере. Перед пилотом сравнить модели на 15–20 взвешенных блюдах: ошибка веса в % видна в «Личных эталонах».

## Как включить настоящую оценку (вместо демо)

1. Подключить Supabase (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`) и применить миграции, включая `0004_photo_meals.sql`.
2. Получить ключ Claude API (console.anthropic.com, оплата картой не из РФ) и положить в секреты функции:
   `supabase secrets set ANTHROPIC_API_KEY=sk-ant-...` (по желанию `PHOTO_MODEL=claude-sonnet-5-5` — точнее, но ≈в 20 раз дороже).
3. `supabase functions deploy photo-estimate`. Приложение само найдёт функцию по адресу `<SUPABASE_URL>/functions/v1/photo-estimate`; в «Как считать» появится «Оценка по фото».
4. Прогнать 15–20 взвешенных блюд и посмотреть ошибку в «Личных эталонах» и «Ваши правки оценок».

Стоимость: Haiku 5.5 — $0,10 / $0,50 за 1 млн токенов, оценка двух снимков ≈ 0,1 ₽. Системный промпт кэшируется.

Ограничения:
- **РФ.** Anthropic API недоступен из России, фото еды — персональные данные (трансграничная передача — вопрос юристу). Функция подходит для контура вне РФ и для тестов; для РФ — та же схема с YandexGPT / GigaChat.
- **Размер снимков.** Модель принимает до 5 МБ на снимок. Сейчас снимок сжимается только качеством JPEG (0,6); если с телефона будут приходить большие файлы — добавить уменьшение до ~1600 px (`expo-image-manipulator`).

## Как запись по фото попадает в дневник

- Пользователь выбирает приём пищи (завтрак / обед / ужин / перекус) — из дневника кнопкой «📷 Сфотографировать» или на вкладке «Фото».
- В черновике главное поле — **вес, г** каждого продукта; рядом видно, сколько предложил ИИ.
- Сохранённый приём (`DayEntry.photoMeals`, пометка «по фото») прибавляется к КБЖУ дня и ничего не затирает. Импорт FatSecret за этот день = цифры FatSecret + приёмы по фото, повторный импорт не задваивает. Удаление приёма вычитает только его. Дальше цифры идут в расход по факту и цели КБЖУ как обычные калории дня. Логика — `src/core/photo/meals.ts`.
- **Правки граммов** (оценка ИИ ≠ сохранённый вес) пишутся в `photoEdits` (на устройстве и в резервной копии) и в `photo_estimates.draft.items[].estGrams` на сервере; представление `photo_edit_errors` даёт ошибку в % по продуктам. Поправка к оценке по этим данным — следующий шаг, когда правок наберётся достаточно.
