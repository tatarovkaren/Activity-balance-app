# Activity Balance — первая версия (MVP)

> Activity Balance — ваш персональный дашборд баланса энергии: тренировки, повседневная активность, питание и вес в одном визуале.
>
> _Activity Balance is your personal energy balance dashboard: workouts, daily activity, nutrition and weight in a single view._

Дневник питания, активности и веса с честным «расходом по факту». Веб-приложение с установкой на главный экран (PWA) и кабинет куратора. Код на Expo (React Native): тот же код позже собирается в приложения для iPhone и Android (этап мобильных приложений с Health Connect и Apple Health).

## Что есть

- **Дневник дня**: вес (Δ к вчера, среднее за неделю, подсказка «взвесьтесь утром»), шаги и цель, КБЖУ (ккал из БЖУ или вручную), тренировка с полем «шаги на тренировке» и оценкой по личному темпу, расход энергии с расшифровкой, баланс за день и 7 дней, замеры с настраиваемой частотой (у женщин бёдра), % жира и норма по возрасту, комментарий, самочувствие, «необычный день» (у женщин — «цикл» с подсказкой).
- **Расход по факту**: адаптивная оценка по ТЗ v35 (56 дней, полураспад 14, доверие 14 взвешиваний / 20 дней с ккал, шаг ±50 ккал, исключение необычных дней и 2–3 дней восстановления, автонаходки «скачок веса» и «неполный дневник» с «вернуть в расчёт»), надёжность, список исключённых дней, мини-график «по факту / по формуле», прогноз даты цели.
- **Графики**: вес и тренд, съедено/потрачено, ожидаемо по дефициту против фактического, % жира; масштаб неделя / месяц / 3 мес / всё / свои даты; выгрузка каждого графика в PNG и PDF (всегда светлая тема).
- **Фото-подсчёт (бета) без привязки к ИИ**: согласие на обработку фото, замер руки (вручную в см, проверка по банковской карте), 2 снимка (сверху и сбоку), черновик по продуктам с диапазоном ±15/20/30 %, скрытое масло, пересчёт уварки под дневник «сухим/сырым», подтверждение в дневник, личные эталоны с ошибкой в %, лимиты тарифа. Провайдеры: ручной ввод, демо, сервер с любой моделью — см. [docs/photo-provider.md](docs/photo-provider.md).
- **Импорт**: FatSecret CSV (один день или период, пустое = нет данных), история веса из CSV, резервная копия JSON (экспорт/импорт без затирания).
- **Профиль**: пол (формулы и нормы), тема (как в системе / светлая / тёмная), рост, дата рождения, цель, белок г/кг, формула БМР, куратор по коду и что ему видно, тариф (переключатель для пилота).
- **Вход**: Google и Apple (через Supabase), почта с кодом; Яндекс ID и VK ID — кнопки есть, нужен отдельный OIDC-шлюз. Без сервера — «Начать без входа» (данные в браузере) и демо.
- **Документы и согласия** (черновики, не проверены юристом): условия использования, политика конфиденциальности, согласие на обработку ПДн и необязательное согласие на рассылки, на русском и английском. Три обязательные галочки и одна необязательная на экране входа, документы и рассылки в профиле, журнал согласий на сервере — см. [docs/legal/README.md](docs/legal/README.md).
- **Кабинет куратора** (широкий экран): все клиенты, статус отчёта, вес и темп, расход по факту, надёжность, дата цели, отчёт дня клиента, комментарий. Без сервера — на демо-клиентах.
- **Сервер**: схема PostgreSQL с правилами доступа на уровне строк — [supabase/migrations/0001_init.sql](supabase/migrations/0001_init.sql). Куратор видит только активных клиентов и только разрешённые поля.

## Запуск

```bash
npm install
npm test              # 22 теста: контрольные примеры ТЗ (2608 ккал, 20,1 %, шаги на кардио, замеры, импорт, фото)
npm run typecheck
npx expo start --web  # разработка
npm run build:web     # сборка в dist/ — статические файлы для любого хостинга
```

## Публикация в интернете (Vercel)

Настройки сборки лежат в `vercel.json`: Vercel сам ставит зависимости, выполняет `npx expo export -p web` и раздаёт папку `dist/`.

1. Войти на https://vercel.com через GitHub (тариф Hobby, бесплатно).
2. Add New → Project → выбрать этот репозиторий → Deploy. Ничего в настройках менять не нужно.
3. Каждое изменение в `main` выкладывается автоматически; у каждого pull request — своя ссылка для предпросмотра.

Ограничения адреса на Vercel: серверы за рубежом, данные пока хранятся только в браузере пользователя. Подходит для показа и пилота на тестовых данных; настоящие персональные данные пользователей из РФ здесь собирать нельзя (242-ФЗ) — для этого облако разворачивается в российском контуре (см. ниже). Поисковикам индексировать адрес запрещено (`robots.txt`, `X-Robots-Tag`).

## Включить облако

1. Создать проект Supabase (для РФ — развернуть в российском облаке: Yandex Cloud, Selectel или VK Cloud).
2. Выполнить `supabase/migrations/0001_init.sql`.
3. Включить провайдеры входа Google и Apple, почту с кодом.
4. Заполнить `.env.local` по образцу `.env.example` и пересобрать.

Синхронизация следует правилам прототипа: локальная копия — рабочая, флаг неотправленных изменений, без флага облако главнее, с флагом заполненные локальные поля побеждают, пустое не затирает заполненное, очищенный день удаляется и в облаке, без связи — повтор через 30 с.

## Структура

- `src/core/` — расчёты без зависимостей от интерфейса (переносятся в мобильные приложения и на сервер как есть): `energy.ts`, `adaptive.ts`, `body.ts`, `importers.ts`, `merge.ts`, `dates.ts` (только местное время), `photo/`.
- `src/legal/`, `docs/legal/` — юридические документы: тексты в Markdown, реквизиты оператора в `src/legal/operator.ts`, пересборка `npm run legal`.
- `src/data/` — хранение, синхронизация, облако.
- `src/screens/`, `src/ui/` — экраны и компоненты.
